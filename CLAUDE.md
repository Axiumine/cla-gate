# CLAUDE.md

Guidance for Claude Code (and humans) working in this repo. [`README.md`](README.md) explains the product and architecture; this file is the operating contract: commands, hard rules, thresholds and tooling gotchas.

## Project

CLA Platform: a GitHub App plus React dashboard that enforces Contributor License Agreements on pull requests. Contributors sign once with GitHub login; every PR gets a `license/cla` Check Run. Stack: Node 26 LTS, Yarn 4, TypeScript 6.0.x, React 19 + Vite 8, Fastify 5, PostgreSQL 18, Kysely, pg-boss.

**Licence: AGPL-3.0-only** (`LICENSE`; `package.json` `"license": "AGPL-3.0-only"`; every source file carries `// SPDX-License-Identifier: AGPL-3.0-only`). Every dependency must be AGPLv3-compatible (the same set as GPLv3: MIT, BSD, ISC, Apache-2.0, LGPL-3.0 and GPL-3.0 are fine; GPL-2.0-only is not); do not add incompatible licences (for example SSPL, BUSL, PolyForm, or Apache-1.x), and do not copy code from incompatible sources. AGPL section 13: the web UI must offer every network user the corresponding source (a visible link in the dashboard footer to the exact repository and commit).

**Status: server foundation built, product not built.** The toolchain is in place and green on all the code that exists: the caps tool (`scripts/check-code-caps.ts` plus `scripts/code-caps/`) and the server foundation in `src/server` and `src/shared` (environment config, pino logging, helmet headers, request ids, error handler, `/healthz` and `/readyz`, Kysely over node-postgres, the forward-only migration runner, `migrations/001_initial.sql` with the whole MVP schema, a PGlite test database that can be swapped for real Postgres). Tooling: `package.json`, Yarn 4, TypeScript, Biome, ESLint, Vitest at 100% coverage, type-coverage, Knip, FTA, the caps ratchet, Lefthook hooks and `.github/workflows/ci.yml` (required jobs `static` and `coverage`, plus the informative `postgres`). There is no GitHub App, webhook, job queue, session, signing route or `src/web` yet, and no placeholder routes, jobs or UI for them; the `GITHUB_*` and `SESSION_SECRET` variables are validated placeholders (`config/env-fields.ts`) that later slices make required. Gates for tools that are not wired (Stryker, Playwright, memlab, Semgrep, Trivy, Qodana) are deferred and marked in the Commands table; they join with their CI jobs. Versions were verified 2026-11-01; re-check with `yarn npm info <pkg> version` before pinning, and update this file when a decision changes.

## Hard rules (non-negotiable)

1. **Never bypass a gate.** No `--no-verify`, no `LEFTHOOK=0`, no lowering a threshold, no growing `.code-caps-baseline.json`, no excluding files from coverage to make it pass. Fix the code. The baseline may only shrink. Sanctioned exceptions, and only these: `LEFTHOOK_EXCLUDE=trivy,semgrep` when offline (CI still enforces them), and the fixed coverage exclusion list under Thresholds.
2. **100% means real.** Every behaviour change ships with tests that assert behaviour. Tests that merely execute lines will die in mutation testing.
3. **No escape hatches without a reason.** `any`, `as` assertions (`type-coverage --strict` penalises them), `@ts-expect-error`, `eslint-disable`, `biome-ignore`, `v8 ignore` are last resorts, each with a written justification on the same line. `reportUnusedDisableDirectives` stays on. Prefer zod parsing and type guards over assertions. The one `as` in the code base (`toExecResult` in `src/server/adapters/db/pglite/results.ts`, PGlite's untyped `exec()` rows) carries `// type-coverage:ignore-next-line -- reason`, which type-coverage honours without a flag. Any `v8 ignore` needs `-- @preserve` or the bundler strips it.
4. **Identity is the numeric GitHub id.** Never key signatures, allowlists or approvals on login or email. Logins and emails are display snapshots.
5. **The signature core, CLA versions and audit rows are immutable.** Enforced by DB triggers that block UPDATE (beyond `revoked_*`), DELETE and TRUNCATE; the runtime DB role must not own the tables. Personal data (name, email, login) lives only in the erasable `signer_pii` table, never in the core or in `audit_log`. Erasure goes through one audited SQL function. Migrations must not weaken any of this. Revocation is prospective only.
6. **Migrations are forward-only.** Never edit a merged migration; add a new one.
7. **No secrets in the repo or logs.** App private key, webhook secret, client secret, session secret live in env or a secret manager. Never log tokens, emails or request bodies. Do not store GitHub user tokens.
8. **New dependency needs justification** (Knip, Trivy, supply-chain cost) **and an AGPLv3-compatible licence.** Yarn's `npmMinimalAgeGate` defaults to 1 day; do not disable it.
9. **Commit or push only when asked.** Do not rewrite history on shared branches.
10. **Keep this file true.** If a decision changes, update `CLAUDE.md` and `README.md` in the same change.

## TypeScript

- Single compiler: `typescript` pinned to `~6.0.x`. **Do not upgrade to 7.x.** TS 7 ships no compiler API (7.1 adds a different one) and typescript-eslint 8.72 peers `typescript <6.1`. Stryker's typescript-checker, `type-coverage --strict` and `scripts/check-code-caps.ts` need the classic API. Revisit when typescript-eslint supports TS 7.1.
- Required compiler options: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `verbatimModuleSyntax`, `erasableSyntaxOnly`. Library code uses `allowImportingTsExtensions` or `rewriteRelativeImportExtensions` as appropriate.
- Project layout: solution-style root `tsconfig.json` (`files: []`) referencing app (bundler resolution, DOM, `noEmit`), server (`nodenext`, `composite`, explicit `rootDir` and `outDir`, emit excludes `**/*.test.ts`), scripts (`nodenext`, `noEmit`), e2e (Playwright specs and `tests/leaks`, `noEmit`), and node-config (`vite.config.ts`, `playwright.config.ts`, Stryker/ESLint config, `noEmit`). Unit tests are co-located and typechecked in their owning project. Every project gets the strict flags, type-coverage and ESLint `projectService` coverage. `package.json` has `"type": "module"`. **Today** the root `tsconfig.json` references `tsconfig.server.json` (`src/server` and `src/shared`: `nodenext`, `composite`, `rootDir: src`, `outDir: dist`, `rewriteRelativeImportExtensions` so `.ts` specifiers become `.js`; excludes `*.test.ts`, `test-support.ts`, `global-setup.ts` and the PGlite adapter, which are test-only), `tsconfig.server.test.json` (`noEmit`, `allowImportingTsExtensions`, the same sources plus every test and helper: this is the project ESLint and type-coverage see for them), `tsconfig.scripts.json` (`scripts/**/*.ts`, `allowImportingTsExtensions`) and `tsconfig.node.json` (`*.config.ts`, `*.config.mjs`, `types/**/*.d.ts`, `allowJs` and `checkJs` so `eslint.config.mjs` is typed and linted); both extend `tsconfig.base.json`, which holds the strict flags plus `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns` and `noFallthroughCasesInSwitch`, and keep their `tsBuildInfoFile` under `node_modules/.tmp`. Referenced `noEmit` projects work with `tsc -b` without `composite`. TS 6 defaults: `strict: true`, `types: []` (list `node` and `vite/client` explicitly), default `rootDir` is the tsconfig dir (set it).
- `tsc -b` is whole-project; gitignore `*.tsbuildinfo` (they live under `node_modules/.tmp`). Caching them in CI is deferred: `ci.yml` caches only the Yarn cache.
- Scripts run natively: `node scripts/foo.ts`. Native type stripping is stable in Node 26 but accepts **erasable syntax only**: no `enum`, no runtime `namespace`, no constructor parameter properties, `import type` for types, explicit `.ts` extensions, and Node ignores `tsconfig.json` (use `#subpath` imports, not `paths`). `typescript` is loaded from `node_modules` as plain JS, which is fine; it must be the 6.x package, and only the default import (`import ts from 'typescript'`) is verified, so do not use named imports until tested.

## Architecture rules

- `src/shared` imports neither `src/server` nor `src/web`. `src/web` never imports `src/server` and vice versa. Enforced by ESLint only (Knip does not check layering): one block per directory in `scripts/eslint-layers.ts`, appended at the end of `eslint.config.mjs`; a later block REPLACES the rule for its files, so each block repeats what it inherits. The patterns are regular expressions on RELATIVE specifiers (a glob on the bare name would also reject `node:stream/web` and `react-dom/server`), dynamic `import()` is covered by `no-restricted-syntax` selectors (`no-restricted-imports` ignores it), and `scripts/eslint-layers.test.ts` lints real snippets for every direction with the real blocks.
- Decision logic (PR evaluation, signature coverage, allowlist matching) lives in `src/server/domain` as pure functions with no I/O. I/O only in `src/server/adapters`. Inside `src/server/domain` ESLint uses an allow-list, not a deny-list of I/O modules: only its own files (no `..`), `src/shared` and `zod` may be imported (so no Node built-in at all, no I/O package, and nothing of `app`, `boot`, `config`, `adapters`, `services` or `src/web`), no dynamic `import()`, no `fetch`, `process`, `require`, `WebSocket`, `XMLHttpRequest` or `EventSource`, and no property access on `globalThis`, `global`, `self` or `window`. Extend the allow-list in `scripts/eslint-layers.ts` (with a test) when a pure module is really needed.
- Validate every external input (HTTP, webhook payloads, GitHub API responses, env) with zod at the boundary. Share schemas through `src/shared`.
- Webhook handler order: verify HMAC on the **raw body** with `crypto.timingSafeEqual`; in **one transaction** insert the `webhook_deliveries` row and enqueue the job; dedupe on `processed_at`; return 2xx. No GitHub API calls in the request path (10 s limit). Accept two webhook secrets during rotation. Jobs re-fetch PR state and never trust the payload.
- Concurrency: serialise evaluation per (repo, PR) **without dropping newer sends**. pg-boss `short` and `exclusive` policies drop a second send; pick a policy that queues per key (check the pg-boss policy docs; candidates are `singleton` or `key_strict_fifo`). The job reads the current head SHA at run time, re-checks it before writing the Check Run and comment, and reads signatures last. PGlite is single-connection, so concurrency tests run against real Postgres.
- `issue_comment` handling: `created` only, issue must be a PR, sender must not be a Bot, a line must be exactly `/recheck`, rate-limited per PR. Also handle `check_run` and `check_suite` `rerequested`, and `pull_request` `closed` (prune pending work). A scheduled sweep re-evaluates open PRs to catch missed deliveries.
- Check Run name is the constant `license/cla`. Do not rename it.
- PR evaluation: the PR opener **and** every non-exempt commit author and committer must be covered (commit emails are spoofable). Committer is exempt if equal to author or GitHub `web-flow`; merge commits are skipped. Covered = same document and signature major equals the active major. List PR commits (cap 250, then page repo commits); use author and committer numeric ids. A `null` or `{}` author means an unlinked email: a first-class failure state with fix instructions, overridable only by an audited per-commit `commit_overrides` row that never implies a signature. `Co-authored-by` trailers have no numeric id: resolve only the `ID+login@users.noreply.github.com` form, otherwise advisory only; ignore bot and AI trailers. Classify bots from the PR opener's account type plus numeric id or app slug, never from email or login strings. Record the covering basis in `pr_evaluations`.
- Authorization: use the installation token and numeric ids to check org role or repo permission, cached with a short TTL. Every query filters by installation id; cross-tenant tests are mandatory. Role matrix is in README.
- Output encoding: CSV export prefixes cells starting with `=`, `+`, `-`, `@`, tab or CR. PR comments and check summaries escape markdown, wrap names in code spans, neutralise `@` and `#`. Hostile-name tests are mandatory.
- Cookies: `__Host-` prefix, `HttpOnly`, `Secure`, `SameSite=Lax`, idle and absolute expiry. Login uses a short-lived Lax state cookie plus PKCE, a **new session id** at the callback, relative-only `return_to`, no mutation on GET. CSRF token plus `Origin` check on state changes; the webhook route is exempt and relies on HMAC only. Delete sessions on a `github_app_authorization` revoke event. Set `trustProxy` correctly or rate limits key on the proxy IP.
- SPA is served by Fastify from the same origin. No tokens in `localStorage`.
- Poison jobs: bounded `retryLimit` plus a dead-letter handler that sets the Check Run to `failure` with a `/recheck` hint.
- Network metadata (IP, user agent) is not recorded unless an explicit config flag enables it. That includes the log: the request serializer in `src/server/adapters/http/logger.ts` emits method and path only (never headers, cookies, query string, body or client address), and a test pins it.
- Server start-up order (`src/server/boot.ts`): `loadConfig(process.env)` (invalid variables are reported by NAME, exit code 1), logger, database, `buildApp`, `listen`, then SIGINT and SIGTERM close the app, which destroys the database; open requests get `shutdownTimeoutMs` (10 s) before their connections are dropped and the exit code becomes 1, and a second signal drops them at once. The HTTP limits (timeouts, keep-alive, 1 MiB body) are explicit in `adapters/http/limits.ts`; failures that never reach a route (bad URL escape, parser errors, oversized headers) are answered by `adapters/http/framework-errors.ts` with the same body, request id and security headers. The runtime connects as `cla_app` (`DATABASE_URL`); only `yarn db:migrate` uses the owner (`MIGRATION_DATABASE_URL`). Wrap every secret in `Secret` (`reveal()` is the one explicit way out). Error responses never carry an exception message.
- No legal text ships by default; maintainers upload their own CLA.

## Testing

- Vitest `projects`: `scripts` and `server` (node environment) today; `web` (jsdom + Testing Library + user-event + jest-dom + MSW 3) joins with `src/web`. Coverage is process-wide, run once with `yarn coverage`. The 100% gate runs in jsdom, not Vitest Browser Mode (v8 coverage is Chromium-only there).
- Database tests use PGlite (single connection, in-memory, Postgres 18) by default. CI also runs the suite against a real Postgres 18 container via `DATABASE_URL` (the informative `postgres` job). `PGlite` is pinned exactly (`0.5.14` is PostgreSQL 18.6); minor upgrades may change on-disk format.
- **How a test gets a database:** import from `src/server/adapters/db/test-support.ts` and nothing else. `migratedTestDatabase()` (all migrations applied) or `emptyTestDatabase()` return `{ kind, db }` on one shared connection per test file and reset the `public` schema (`drop schema public cascade`) before each call, so tests never see each other's rows. `migratedRuntimeDatabase()` is the same with `cla_app` created first, so its grants exist, and `containing(text)` is a typed `expect.stringContaining` for error-message matchers (assert the message, not only the SQLSTATE, so a dropped trigger cannot hide behind another one that raises the same code). `seedTenant(db, n)` inserts an installation, repository, document and published version 1.0 with ids derived from `n` (two tenants: `n = 1, 2`), `seedSignature(db, tenant, githubUserId)` adds a user, signature and `signer_pii`, `publishVersion` adds a version, `ensureRuntimeRole(db)` creates `cla_app` (a cluster-wide object) and `asRuntimeRole(db, work)` runs `work` in a transaction under `set local role cla_app`, which is how tests prove what the unprivileged role can and cannot do. `realPostgres` is true when the run uses a server; use `test.skipIf(!realPostgres)` only for what PGlite cannot do (today only the advisory-lock contention test). Files run one at a time on a real server (`fileParallelism: !realPostgres`), in parallel on PGlite. Tests that need a migrations folder use `writeMigrationDirectory({ name: sql })`.
- **Real-server runs:** with `DATABASE_URL` set, `src/server/adapters/db/global-setup.ts` creates `cla_test_<hex>` (the user needs CREATEDB), hands the URL to the workers through Vitest's `provide`/`inject`, and drops the database afterwards. It never touches the database the URL names.
- Snapshots: `toMatchInlineSnapshot` for small values; `toMatchSnapshot` only for small structural output where an inline literal would be noise; `toMatchFileSnapshot` for API JSON and CSV export, into a dedicated directory, never `__snapshots__/*.snap`. With `CI` set Vitest writes no snapshots and fails on missing ones; outside CI it writes them and passes, so the gate always runs with `CI=1` and new snapshot files must be committed.
- Vitest 5 defaults: `clearMocks: true`, fails on unawaited `expect().resolves/rejects`, no config search in parent dirs, reports under `.vitest/`. `vite` is now an explicit peer: add it as a devDependency. `@vitest/coverage-v8` must match the exact Vitest version.
- Vitest `related` needs `--run` and `--passWithNoTests`; never add `--coverage` to it (100% thresholds fail on partial runs).
- Stryker: use `@stryker-mutator/*` 10.1+ (Vitest 5 support landed in 10.1.0). It forces coverage off and one worker, so mutate only the node/unit project. Open bugs: `--logLevel debug` crashes on Vitest 5 (#6272), nondeterministic perTest verdicts (#6073); Browser Mode unsupported. Gitignore `.stryker-tmp`; cache `reports/stryker-incremental.json` in CI. Incremental misses dependency, env and snapshot changes: use `--force` after those.
- Playwright: visual baselines come from one environment. Image tag must equal the package version exactly (`mcr.microsoft.com/playwright:v<version>-noble`), run with `--init --ipc=host`. Never regenerate baselines on the host. Omit `{platform}` from `snapshotPathTemplate`. `animations: 'disabled'` is default; set `maxDiffPixels` explicitly. Bump image and package together.
- memlab 2.x drives Chromium through Puppeteer (separate browser download; `--chromium-binary` can reuse one). No leak-based exit code was found (unverified). Wrap it with `@memlab/api` `run()` and fail on `leaks.length`; the wrapper lives in `tests/leaks/`. Node 26 compatibility is unverified: smoke-test first. Use `vitest --logHeapUsage` and `node --heap-prof` / `--cpu-prof` for diagnosis.

## Tooling gotchas

- **Corepack is not bundled with Node 25+.** `npm install -g corepack` before `corepack enable` (also in Dockerfiles and CI). Node 26 Linux binaries link `libatomic`; slim images may need it.
- **Yarn Berry never runs `prepare`.** Install hooks from root `postinstall` (`scripts/dev/install-hooks.ts` runs `lefthook install`, and skips it when `CI` is set or there is no `.git`). **CI must install no hooks**: on a persistent workspace `actions/checkout` deletes `node_modules` (`git clean -ffdx`) and then `git checkout` fires `post-checkout`, which with `assert_lefthook_installed: true` fails when Lefthook is gone (verified). Docker builds have no `.git`: the script skips there, and `yarn install --immutable --mode=skip-build` skips scripts altogether. Yarn 4.14+ defaults `enableScripts` to false, so third-party postinstalls (including lefthook's own) are skipped; root-workspace scripts still run.
- `.yarnrc.yml`: `nodeLinker: node-modules` (PnP has known Playwright bugs and unverified support elsewhere). `yarn install --immutable` in CI. **The file must be committed**: without it a clean checkout installs with Yarn's default PnP linker, and ESLint (`.pnp.loader.mjs` not found by the project service) and Vitest (`Non-utf8 buffers are not supported`, yarnpkg/berry#4942) fail. Some global git ignores list it (the maintainer's `~/.config/git/ignore` does), so the repo `.gitignore` re-includes it with `!.yarnrc.yml`; check `git status` shows it before pushing.
- Node version sources: `.nvmrc`, `mise.toml`, `devEngines.runtime`, `packageManager` (with hash, written by `corepack use yarn@4.x`). Node ignores `engines`; Yarn does not enforce it. mise ignores `.nvmrc` unless configured, so `mise.toml` is canonical. fnm `--corepack-enabled` fails on Node 25+.
- **Lefthook v2**: use `jobs:` (list order is run order). `files` is a shell command, not a pattern. Set `glob_matcher: doublestar` or `**/*.ts` misses root files. `stage_fixed` is pre-commit only. Default execution is sequential and does not stop on failure: use `piped: true` for fail-fast, `group:` for nested parallel. `parallel` and `piped` together is an error. - **Server foundation facts** (verified while building it, 2026-11-01):
  - Dependencies: `fastify` 5.12, `@fastify/helmet` 13, `fastify-type-provider-zod` 7 (its peers `@fastify/swagger` and `openapi-types` are optional for us: Yarn prints YN0002/YN0086, accepted), `zod` 4.6, `kysely` 0.29.7 (0.29.8 was younger than the one-day age gate), `pg` 8.23, `pino` 10.4; dev `@electric-sql/pglite` 0.5.14 (exact; Apache-2.0). All are MIT except PGlite, all AGPL-compatible.
  - Fastify's `trustProxy` type has no number, but the runtime accepts a hop count: `app.ts` converts a count into the equivalent `(address, hop) => hop < n` function. `parseTrustProxy` returns `undefined` on a typo, which `loadConfig` turns into a start-up error naming `TRUST_PROXY`.
  - node-postgres returns bigint (int8) as a string. `pg.ts` and the PGlite client both parse it with `parseInt8` (throws `RangeError` outside the safe-integer range), so ids are numbers everywhere and the two drivers agree. Hand-written `schema.ts` types follow that, and `schema.test.ts` compares them with the live catalog.
  - PGlite 0.5.14 is PostgreSQL 18.6, enforces roles and `SET ROLE` privileges (so the runtime-role tests are meaningful on it too), starts in about half a second, and `query()` always uses the extended protocol, which rejects multi-statement scripts: the own Kysely dialect in `adapters/db/pglite*` sends parameterless SQL through `exec()`. Kysely starts its driver lazily and `destroy()` is a no-op before that, hence the `select 1` ping in `openPgliteDatabase`. It has one connection, so the dialect queues with a mutex; a test that needs two competing connections (advisory locks) must run on a real server.
  - Test resets use `drop schema public cascade; create schema public`; roles are cluster-wide and survive it. A `TRUNCATE` of a table that other tables reference fails with `0A000` before any trigger fires, so the immutability tests use `truncate ... cascade` to reach the trigger.
  - ESLint outcomes worth knowing: `sonarjs/function-return-type` accepts a function with a JSDoc `@returns` tag (used for functions that return a union by design); `security/detect-object-injection` is avoided with a `Map` (`STATUS_TEXT`) or an inline reason; `expect.any(...)`, `expect.stringContaining(...)` are typed `any` and trip `no-unsafe-assignment` inside object literals, so tests wrap them in an `unknown`-returning helper; a Fastify plugin with no `await` is written as `FastifyPluginCallbackZod` (`done()`) to satisfy `require-await`; `Promise.withResolvers<void>()` trips `no-invalid-void-type`, annotate the variable as `PromiseWithResolvers<void>` instead.
  - `docker-compose.yml` mounts the volume at `/var/lib/postgresql` (the 18 image keeps its cluster in `18/docker` below it). The host port is `${POSTGRES_PORT}` with no default (never 5432, often taken): `yarn db:up` picks a random free one; to probe by hand set `POSTGRES_PORT` to a free port, use a unique `-p <project>`, and finish with `down -v`.

## Code caps tool

`node scripts/check-code-caps.ts` (entry) with the logic in `scripts/code-caps/` (`types`, `naming`, `nesting`, `collector`, `measure`, `files`, `baseline`, `report`, `cli`; tests are co-located, `test-support.ts` holds the shared helpers). It is a port of the maintainer's Python tool `check_code_caps.py` and writes the same baseline format (`{"version": 1, "caps": {...}, "violations": {"<path>::<kind>::<name>": value}}`).

- Flags: `--root <dir>`, `--init` (first run only), `--force` (with `--init`), `--update-baseline` (ratchets down, refuses new or grown violations). **Agents never run `--init`, `--force` or `--update-baseline` to hide a violation: fix the code.** Exit codes: 0 ok, 1 new or grown violation, 2 unusable input (syntax error, corrupt baseline, unknown option).
- Measures every `.ts .tsx .mts .cts .js .jsx .mjs .cjs` file. Inside git: tracked plus untracked-not-ignored, so **`.gitignore` must list build and report output** (`coverage dist build reports playwright-report test-results .stryker-tmp .vitest`); git mode does not prune those by name. Outside git (plain walk) those output dirs are pruned by name. Tool dirs `.git .gitnexus .claude .idea .yarn node_modules` are skipped at any depth in both modes. A source-extension file name that is not valid UTF-8 is an error (exit 2), never skipped.
- Counts: function = any function-like node with a body (declarations, expressions, arrows, methods, constructors, accessors, static blocks), decorators and modifiers included in its span; params = parameters (a fake `this` is free; rest counts one; parameter properties count); nesting = if/for/for-in/for-of/while/do/try/switch/with levels inside one function (`else if` does not deepen, `else { if }` does; bare blocks and labels are transparent; nested functions and callbacks are measured on their own).
- Names are qualified (`Class.method`, `outer.inner`, `Namespace.fn`, `config.handler` for a function inside a named object literal). Unnamed functions take the name of the variable, property or assignment target that receives them (parentheses, `as`, `satisfies`, `!` and `<T>` wrappers are looked through), `default` for a default export, else `<anonymous>`. A callback passed to a call is named from the call, not its position: `describe("title")`, `items.map()`, so fixing one callback never renumbers the baseline keys of its siblings. Remaining repeats get `#2`, `#3`. Keys sort by code point (not locale), so the order is the same on every machine. Names and paths are escaped (`\xNN`) when printed so control characters cannot forge report lines.
- Baseline write is atomic (temp file plus rename). Any unexpected failure while measuring a file is reported as `<path>: cannot measure: ...` (exit 2).
- Known differences from the Python original, accepted: no `--help` or argparse prefix abbreviations (unknown options exit 2), lenient UTF-8 decoding of file contents, TS parser rejects sloppy-mode JS octal literals, TS syntax inside a `.js` file is a parse error, a nonexistent `--root` exits 2, lines split on `\n`, `\r\n`, `\r`, U+2028, U+2029 only, an empty `switch {}` has depth 0. Not guarded: huge files, symlinks pointing outside the root, baseline `version` validation.
- Needs the `typescript` 6.x package (classic compiler API), default import only. Syntax errors are detected through a one-file `ts.createProgram` (`getSyntacticDiagnostics`) and exit with 2.

## Repository protection

Repo: `Axiumine/cla-gate` (public, `main`). Branch protection on `main`, set 2026-11-01 and applied to admins too (`enforce_admins`):

- Required status checks: `static` and `coverage` (not strict, so a branch need not be up to date). These are the exact job names the CI workflow must use; renaming a job breaks the rule.
- Linear history required (squash or rebase merges only), force pushes and deletion blocked, conversation resolution required.
- No required reviews (single maintainer; a self-approval is impossible).
- Consequence: there are no direct pushes to `main`. Every change, including docs, goes through a PR whose two checks pass. `.github/workflows/ci.yml` defines real `static` and `coverage` jobs (never placeholders that always pass); a PR can merge only while they exist and pass.
- Emergency unblock (maintainer only, re-add the checks afterwards): `gh api -X DELETE repos/Axiumine/cla-gate/branches/main/protection/required_status_checks`.
- CI runs on the maintainer's shared self-hosted runners (`[self-hosted, Linux, X64]`) with the fork-PR approval gate (`all_external_contributors`) as the only protection: read the WHOLE diff before approving a fork run. Ports are random, free, loopback only, 32769-60999 (`yarn dev` and every test that listens pick one; the app's own default `PORT` 3000 for `yarn start` is the one recorded exception). Jobs have a timeout of at most 60 minutes, no `container:` or `services:`, no git hooks, and keep all tool state under `$RUNNER_TEMP`. `release.yml` and `scorecard.yml` (any file named like them) stay on `ubuntu-24.04`. Full policy and the checklist: `docs/ci-runners.md`; `yarn ci:runners` guards it.
- Add `e2e`, `mutation`, `semgrep` or `trivy` as required checks only after they are stable in CI. If this protection changes, update this section in the same PR.
