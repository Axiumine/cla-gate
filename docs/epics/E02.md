# E02 — Quality-gate toolchain and CI

**Bounded Context:** BC-08
**Priority:** 🔴 Must have
**Status:** ✅ Done

**Goal:** One strict, reproducible toolchain checks every change the same way on a laptop and in CI: pinned runtime, strict TypeScript, zero lint findings, 100% coverage, 100% type coverage and no unused code. Hooks give fast feedback; CI is the authority because hooks are bypassable.
**Depends on:** E01.
**Out of scope:** The structure-cap ratchet tool itself (E03). Gates for tools that are not wired yet, namely Stryker, Playwright, memlab, Semgrep, Trivy and Qodana, with their scripts, hook jobs and CI jobs (E20). The server and web TypeScript projects, Vitest projects and ESLint layering rules, which arrive with the code they govern (E04, E17). Container build and deployment (E19). The CI runner policy, its guard and the helpers for ports and CI containers (E23).

---

**E02-S01 — Pin the runtime and the package manager** ✅ Done
Acceptance criteria:
- Node 26.13.0 is declared in three places that agree: `.nvmrc` (`26.13.0`), `mise.toml` (`[tools] node = "26.13.0"`, canonical because mise ignores `.nvmrc` unless configured) and `package.json` `devEngines.runtime` (`name: node`, `version: 26.13.0`, `onFail: error`). The CI workflow reads `.nvmrc`, so it cannot drift.
- `package.json` sets `"type": "module"` and `packageManager` to `yarn@4.18.1+sha512...` with the hash written by Corepack.
- `.yarnrc.yml` is committed and contains the single setting `nodeLinker: node-modules`; Yarn's `npmMinimalAgeGate` stays at its one-day default (hard rule 8), and PnP is not used because of known Playwright bugs.
- `yarn.lock` is committed, and CI installs with `yarn install --immutable`, so a lockfile drift fails the job.
- Corepack is not bundled with Node 25+, so the documented bootstrap is `npm install -g corepack && corepack enable` (`docs/development.md` "Setup and run" and `docs/tooling-gotchas.md`), and CI pins `corepack@0.36.0`, installed with `npm install --global --prefix "$RUNNER_TEMP/npm-global"` into a per-job prefix and never into the tool-cache Node.
- The root `postinstall` script (`scripts/dev/install-hooks.ts`) runs `lefthook install`, because Yarn Berry never runs `prepare`, and skips it when `CI` is set or there is no `.git`; the Docker case without `.git` is documented as `yarn install --immutable --mode=skip-build`.
- `typescript` is `~6.0.3`, `vite` is an explicit devDependency (a Vitest 5 peer), and `@vitest/coverage-v8` equals the Vitest version exactly (`5.0.5`).

**E02-S02 — Configure strict TypeScript projects and type coverage** ✅ Done
Acceptance criteria:
- `tsconfig.base.json` sets `target` and `lib` `ES2025`, `module` and `moduleResolution` `nodenext`, `moduleDetection: force`, `types: ["node"]`, `noEmit`, `skipLibCheck`, and the strict flags `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `verbatimModuleSyntax`, `erasableSyntaxOnly`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns` and `noFallthroughCasesInSwitch`.
- The root `tsconfig.json` is solution-style (`"files": []`) and references `tsconfig.scripts.json` (`scripts/**/*.ts`, `allowImportingTsExtensions`) and `tsconfig.node.json` (`*.config.ts`, `*.config.mjs`, `types/**/*.d.ts`, `allowJs` and `checkJs` so `eslint.config.mjs` is typed). Both extend the base and keep their `tsBuildInfoFile` under `node_modules/.tmp`.
- `yarn typecheck` runs `tsc -b` and passes; `*.tsbuildinfo` is git-ignored (E01-S05).
- `yarn type-coverage` runs `type-coverage --strict --at-least 100 -p <project>` once for `tsconfig.scripts.json` and once for `tsconfig.node.json`, and reports 100% for each.
- Because `type-coverage` does not follow project references (on the solution root it reports 0 / 0 and passes), `docs/tooling-gotchas.md` requires one line per new tsconfig project in the script. This rule is what E04 and E17 follow when they add projects.
- TypeScript stays on 6.0.x on purpose: TypeScript 7 ships no classic compiler API, which the caps tool, `type-coverage --strict` and typescript-eslint need. The reason is written in `docs/decisions.md` "Decisions" and in `docs/quality-gates.md` (TypeScript), and Dependabot enforces it (E01-S06).
- Scripts run natively with `node scripts/foo.ts`, which accepts erasable syntax only; `docs/quality-gates.md` (TypeScript) lists the consequences (no `enum`, no runtime `namespace`, no parameter properties, `import type`, explicit `.ts` extensions, `#subpath` imports instead of `paths`).

**E02-S03 — Format and lint with Biome** ✅ Done
Acceptance criteria:
- `@biomejs/biome` is pinned exactly (`2.6.4`). `biome.json` is a root config with `vcs` enabled (`clientKind: git`, `useIgnoreFile: true`), `files.ignoreUnknown: true` and `files.includes: ["**"]`.
- Style is 2-space indent, single quotes and `lineWidth` 120; Biome also formats the YAML under `.github/` and `lefthook.yml`.
- `linter.rules.preset` is `recommended`; `complexity/noExcessiveCognitiveComplexity` is set to level `error` with `maxAllowedComplexity: 10` (its default severity is `info`, which would not fail anything).
- `complexity/useLiteralKeys` is off because it rewrites `record['key']` to `record.key`, which `noPropertyAccessFromIndexSignature` forbids.
- `assist.actions.source.organizeImports` is `on`.
- The Markdown formatter and linter are off, because Biome's Markdown formatter pads table separators and the project tables use the `|---|---|` style.
- `yarn lint:biome` runs `biome ci --error-on-warnings .` (read-only, any warning fails); `yarn format` runs `biome check --write .`; `yarn lint` runs Biome and then ESLint.
- `eslint-plugin-jsx-a11y` is not used (its peers stop at ESLint 9); accessibility rules come from Biome when the web code lands (E17).

**E02-S04 — Lint with ESLint 10, type-aware rules, SonarJS and security rules** ✅ Done
Acceptance criteria:
- `eslint.config.mjs` is a flat config using `defineConfig` and `globalIgnores`; it ignores `node_modules`, `dist`, `build`, `coverage`, `reports`, `.vitest`, `.stryker-tmp`, `playwright-report`, `test-results` and `.yarn`.
- Rules apply to every extension the caps tool measures (`**/*.{ts,tsx,mts,cts,js,jsx,mjs,cjs}`), so a `.tsx` or `.cjs` file cannot skip them; a file that no tsconfig project includes fails with a project-service parse error, which is intended.
- The config extends `@eslint/js` recommended, `typescript-eslint` `strictTypeChecked` and `stylisticTypeChecked`, and SonarJS recommended, with `projectService: true` and `tsconfigRootDir: import.meta.dirname`.
- `reportUnusedDisableDirectives` is `error`. Every inline `eslint-disable` in the repository carries a written reason after `--`.
- Overrides: `@typescript-eslint/restrict-template-expressions` allows numbers; `@typescript-eslint/switch-exhaustiveness-check` is `error` (it is not in `strictTypeChecked`, and Biome's counterpart is still nursery); `sonarjs/cognitive-complexity` is off because Biome owns it.
- Size and complexity caps are errors: `complexity` 10, `max-lines` 500, `max-lines-per-function` 50, `max-params` 4, `max-depth` 4, with `skipBlankLines` and `skipComments` false so the counting matches the caps tool (E03). The one known difference is that `max-params` also counts a typed `this` parameter; ESLint is the stricter side.
- `eslint-plugin-security`'s recommended rules are all escalated from `warn` to `error`, and `eslint-plugin-no-unsanitized` recommended is enabled, with the ambient declaration `types/eslint-plugin-no-unsanitized.d.ts` because the package ships no types.
- `eslint-config-biome` is deliberately not used: it would switch off the type-aware `no-floating-promises`, `no-misused-promises` and `switch-exhaustiveness-check`. The reason is recorded in the config header and in `docs/tooling-gotchas.md`.
- `yarn lint:eslint` runs `eslint . --max-warnings 0 --no-warn-ignored` without `--cache` (cached results go stale for type-aware rules).

**E02-S05 — Test with Vitest at 100% v8 coverage** ✅ Done
Acceptance criteria:
- `vitest.config.ts` defines one project today, `scripts` (`environment: node`, `include: ['scripts/**/*.test.ts']`, `extends: true`); further projects join with the code they test (E04, E17).
- Coverage uses the `v8` provider with `include: ['src/**/*.{ts,tsx}', 'scripts/**/*.ts']`, so files that no test loads still count, and `thresholds: { 100: true }` (lines, branches, functions and statements).
- The exclusion list is fixed and is the only one: `coverage.exclude` is `**/*.test.{ts,tsx}`, `**/*.d.ts`, `e2e/**` and `tests/leaks/**`. `docs/quality-gates.md` (Thresholds) also reserves test setup files and MSW handlers, which join the list only when such files exist; root tooling configs are outside `coverage.include`. Hard rule 1 forbids extending the list or lowering a threshold to make a run pass.
- `yarn test` runs `vitest run`; `yarn coverage` runs `CI=1 vitest run --coverage`, and `CI=1` makes Vitest refuse to write new snapshots, so a push cannot go green with an uncommitted snapshot file.
- The suite passes with 100% in all four measures (144 tests in 8 files on 2026-11-01), and `vitest related --run --passWithNoTests` is the pre-commit variant, which never gets `--coverage` because partial runs fail the thresholds.
- Test conventions are written in `docs/quality-gates.md` (Thresholds, Testing): tests obey the same structure caps as source, so they are flat `test()` and `test.each()` tables with no `describe` wrapper around a whole file, at most four parameters or fixtures per test, files split by topic and co-located as `*.test.ts`.
- Snapshot policy is written in `docs/quality-gates.md` (Testing): inline for small values, `toMatchFileSnapshot` for API JSON and CSV in a dedicated directory, never `__snapshots__/*.snap`.

**E02-S06 — Gate unused code and complexity with Knip and FTA** ✅ Done
Acceptance criteria:
- `knip.json` has entry `scripts/*.ts!`, and project `scripts/**/*.ts!`, `!scripts/code-caps/test-support.ts!`, `*.{ts,mjs}` and `types/**/*.d.ts`.
- `yarn knip` runs `knip && knip --production --strict` and exits 0 in both modes, because `--strict` implies production mode and ignores devDependencies, hence two runs.
- Exports that only tests use carry an `@internal` tag, which Knip ignores in production mode; the repository has no other Knip suppression.
- `fta-cli` is pinned exactly (`3.1.0`, because v2 and v3 changed scoring) and `yarn fta` runs `fta . --config-path fta.json`.
- `fta.json` sets `score_cap: 50`, `output_limit: 100`, `exclude_filenames` (`*.test.ts`, `*.test.tsx`, `test-support.ts`, `*.d.ts`) and `exclude_directories` (`/node_modules`, `/coverage`, `/dist`, `/build`, `/reports`, `/.vitest`, `/.yarn`, `/.stryker-tmp`).
- The run passes with the highest file at 48.46 (`scripts/code-caps/cli.ts`). A score above 50 fails; exactly 50 is ambiguous in FTA's docs and is treated as a failure risk. Splitting a file is the only way to lower its score, which is why `collector.ts`, `nesting.ts` and `report.ts` exist.
- `docs/tooling-gotchas.md` records that FTA exits at the first file above the cap without a report, so the full list needs a second run with a raised cap and `--json`.
- `docs/tooling-gotchas.md` records that `fta-cli` 3.1.0 ships CRLF line endings, so it must be run through `yarn fta` (Yarn launches it with `node`), never through `node_modules/.bin/fta`.

**E02-S07 — Run the gates locally with Lefthook** ✅ Done
Acceptance criteria:
- `lefthook.yml` uses the v2 `jobs:` syntax with `min_version: 2.0.0`, `assert_lefthook_installed: true` and `glob_matcher: doublestar`; hooks are installed by the root `postinstall`.
- `pre-commit` is `piped: true`: first `biome check --write --error-on-warnings` on staged files with `stage_fixed: true`, then a parallel group of `eslint --max-warnings 0 --no-warn-ignored` on staged `**/*.{ts,mjs}`, `vitest related --run --passWithNoTests` on staged `**/*.ts`, and `yarn caps`. The ESLint and Vitest jobs carry `skip: [merge, rebase]`.
- `pre-push` is `piped: true` and calls the same `package.json` scripts as CI: `yarn lint:biome`, `yarn typecheck`, a parallel group (`yarn lint:eslint`, `yarn type-coverage`, `yarn knip`, `yarn fta`, `yarn caps`, `yarn ci:runners`) and last `yarn coverage`. It has no `skip`, so `yarn gate` can never exit 0 without running anything during a rebase.
- `yarn gate` runs `lefthook run pre-push --all-files` and is the local equivalent of the CI `static` plus `coverage` jobs.
- `post-merge`, `post-checkout` and `post-rewrite` run `yarn install --immutable` only when `yarn.lock` or `.yarnrc.yml` changed.
- Ordering rationale is written in `docs/toolchain.md` "Hook pipeline": cheap and deterministic first, formatting before linting, types before tests, coverage last.
- A hook job exists only if CI has a counterpart, which is why no Trivy or Semgrep job is in the file yet (E20). The only sanctioned local exclusion is `LEFTHOOK_EXCLUDE=trivy,semgrep` when offline, and hard rule 1 forbids `--no-verify` and `LEFTHOOK=0`.
- Hook jobs that mirror CI jobs follow [CI runners, ports and fork approval](../ci-runners.md): the runner guard `yarn ci:runners` runs in `pre-push` as it does in the CI `static` job, and no git hook is installed in CI.

**E02-S08 — Run the gates in CI with SHA-pinned Actions** ✅ Done
Acceptance criteria:
- `.github/workflows/ci.yml` is named `CI`, runs on `pull_request` and on `push` to `main`, and declares `permissions: contents: read` at workflow level.
- `concurrency.group` is `ci-${{ github.ref }}` and cancels in-progress runs only for pull requests, never for pushes to `main`.
- Two independent jobs, `static` and `coverage`, both on the literal `[self-hosted, Linux, X64]` with `timeout-minutes: 15` and no `needs`, so a skipped dependent job cannot mask a failure. Their names are the required checks of E01-S03.
- Each job starts with a preflight step and a step that keeps tool state in `$RUNNER_TEMP`, checks out with `persist-credentials: false` and `clean: true`, sets up Node from `.nvmrc` with `package-manager-cache: false`, enables Corepack at the pinned version, restores the Yarn cache keyed on `hashFiles('yarn.lock')` and installs with `yarn install --immutable`.
- `static` has explicit, individually named steps in this order: Biome, `tsc -b`, ESLint, type coverage per project, Knip in both modes, FTA, code caps, runner guard (`yarn ci:runners`). Each step runs the `package.json` script that `pre-push` runs.
- `coverage` runs `yarn coverage` (`CI=1 vitest run --coverage`, 100% thresholds).
- Every third-party Action is pinned to a full commit SHA with its version in a comment (`actions/checkout` v7.0.1, `actions/setup-node` v7.1.0, `actions/cache` v6.1.0); Dependabot keeps them current (E01-S06).
- The workflow uses no secrets, no `pull_request_target`, and interpolates no untrusted input into a `run:` block; `COREPACK_ENABLE_DOWNLOAD_PROMPT` and `YARN_ENABLE_TELEMETRY` are set to `0`.
- Caching the `tsc -b` build info is deferred and documented in `docs/quality-gates.md` (TypeScript); the cache covers only the Yarn cache today.
- CI jobs, containers and ports of this story follow [CI runners, ports and fork approval](../ci-runners.md): shared self-hosted runners, literal `runs-on`, random free loopback port above 32768, timeouts and cleanup, release/scorecard on GitHub-hosted.
