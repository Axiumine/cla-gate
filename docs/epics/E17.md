# E17 — Web application shell and design system

**Bounded Context:** BC-06
**Priority:** 🔴 Must have
**Status:** ⬜ Todo

**Goal:** Provide one accessible, themeable, CSP-clean React foundation that Fastify serves from the API's own origin and that talks to the API only through typed `src/shared` contracts. The feature screens of E18 and the setup page of E19 then add no tooling, auth or security plumbing of their own.
**Depends on:** E10, E23.
**Out of scope:** Feature screens (E18) and the first-run setup page (E19). Issuing sessions, CSRF tokens and the login redirect (E10; this epic only consumes them). Playwright configuration, visual baselines and the e2e job (the harness is E20-S06; the screen specs are E18-S12). Locales other than English. React Compiler (off in v0, see `docs/decisions.md` Decisions). Stryker coverage of `src/web` (outside the mutation floor until a plan exists).

**E17-S01 — Web project scaffold that passes every gate** ⬜ Todo
An empty but real single-page app, so the web project is under every gate before the first screen exists.
Acceptance criteria:
- `tsconfig.web.json` extends `tsconfig.base.json` (so all strict flags apply): `moduleResolution: bundler`, `lib` with `DOM` and `DOM.Iterable`, `jsx: react-jsx`, `noEmit`, `types: ["vite/client"]`, includes `src/web/**/*` and `src/shared/**/*`. It is referenced from the solution-style root `tsconfig.json`, `yarn typecheck` builds it, and `yarn type-coverage` gains one `-p tsconfig.web.json` invocation that passes at 100%.
- `vite.config.ts` (node-config project) uses `@vitejs/plugin-react` 6 with no Babel and no React Compiler, `build.outDir: dist/web`, `build.assetsInlineLimit: 0` (no `data:` URIs, which the CSP forbids), and `server.proxy` forwarding `/api`, `/healthz` and `/readyz` to the Fastify dev server on the loopback `PORT` that `yarn dev` picked (a random free port above 32768, never 3000).
- `yarn build` runs `tsc -b` then `vite build` and leaves `dist/server` and `dist/web`; `yarn dev` runs Vite and the Fastify dev server together through a script in `scripts/dev/` built on `scripts/dev/db.ts run app` (no new dependency; both servers listen on random free loopback ports above 32768, and Vite's is never 5173), which stops both on SIGINT or SIGTERM and exits non-zero when either child dies. `docs/development.md` Commands table and Setup and run section are updated in the same change.
- `src/web/index.html` has exactly one `<script type="module" src>`, no inline script, no inline `<style>`, no `on*=` attribute, `<html lang="en">`, a viewport meta tag and a `<title>`. `src/web/main.tsx` only mounts `<App />` into `#root` and is covered by a mount test.
- Vitest `web` project in `vitest.config.ts`: `jsdom` environment, `include: src/web/**/*.test.{ts,tsx}`, a setup file registering `@testing-library/jest-dom/vitest`, automatic RTL cleanup and an MSW 3 server with `onUnhandledRequest: 'error'` (an unexpected request fails the test). The setup file and MSW handler files join the coverage exclusion list in `docs/quality-gates.md` Thresholds, and nothing else does.
- `src/web/test-support/render.tsx` exports `renderWithProviders(ui, { route, session })` (QueryClient with `retry: false`, router, i18n and theme providers added by later stories as they land) and `src/web/test-support/server.ts` exports the shared MSW server; both are used by the placeholder `App` test.
- ESLint override for `src/web/**`: `no-restricted-imports` blocks imports of `src/server/**` (and `src/shared` stays barred from importing either side, per `docs/architecture.md`); `eslint-plugin-react-hooks` 7 `configs.flat.recommended` is on with `--max-warnings 0`. Biome `a11y` group is set to `error` for `src/web/**`; `lint/security/noDangerouslySetInnerHtml` stays `error`. Knip production entry is `src/web/main.tsx!`; both Knip modes report zero issues.
- Dependencies added here are only those this story uses: `react`, `react-dom` (identical exact versions), `@vitejs/plugin-react`, `jsdom`, `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`, `msw`. Each is MIT and AGPLv3-compatible, with the justification recorded in the PR; `npmMinimalAgeGate` is untouched. Later stories add the dependency they first import, because Knip rejects unused ones.
- `fta.json` `exclude_filenames` covers `*.test.tsx` and `src/web/test-support/**`; every `src/web` source file scores 50 or below and respects `yarn caps` (function 50 lines, 4 parameters, nesting 4), with the baseline unchanged.
- Dev servers and CI jobs of this story follow [CI runners, ports and fork approval](../ci-runners.md): Vite and the Fastify dev server listen on random free loopback ports above 32768 (never 3000 or 5173), and any CI job added for the web project runs on the shared self-hosted runners with a literal `runs-on`, a timeout and cleanup.

**E17-S02 — Message catalog for i18n-ready strings** ⬜ Todo
English only, but no user-visible string is ever written inline, so a second language later is a catalog addition and not a refactor.
Acceptance criteria:
- `src/web/i18n/messages.ts` exports the English catalog as a flat `as const` object with dotted keys (`common.close`, `errors.forbidden`); `MessageKey` is derived from it. Test: every key matches `^[a-z][A-Za-z0-9]*(\.[a-z][A-Za-z0-9]*)+$` and every value is a non-empty string.
- `t(key, params?)` replaces `{name}` placeholders. The parameter object type is derived from the placeholders in the message literal, so a missing or misspelt parameter fails `tsc`. A value containing `{` that is not a placeholder is returned untouched (parameter values are never re-interpreted as placeholders; test with `{name}` supplied as a parameter value).
- Plurals use `Intl.PluralRules('en')` through `t.plural(key, count)`, which picks `<key>.one` or `<key>.other`; a catalog test fails when a `.one` key has no `.other` sibling or the sibling uses different placeholders.
- `I18nProvider` supplies the locale (`en`) and sets `document.documentElement.lang`; `useT()` is the only way components read messages. Formatters `formatNumber`, `formatDate` and `formatDateTime` wrap `Intl` with the provider locale. `<Timestamp value utc />` renders a `<time dateTime="<ISO-8601>">`; evidence timestamps (`signed_at`, `published_at`, audit time) pass `utc` and show `YYYY-MM-DD HH:mm UTC`, everything else shows the viewer's local time zone.
- ESLint `no-restricted-syntax` in non-test `src/web/**/*.tsx` fails `yarn lint` on JSX text containing a letter and on a string literal in `aria-label`, `title`, `placeholder`, `alt` or `label` props. Test files are exempt; the selector list lives in `eslint.config.mjs`.

**E17-S03 — SPA serving from Fastify with a CSP-clean response** ⬜ Todo
Acceptance criteria:
- `@fastify/static` (MIT, justification recorded) serves `dist/web` from the same origin when the directory exists. The directory is configurable through `WEB_ROOT` (default: resolved relative to `dist/server`), and `NODE_ENV=development` serves nothing because Vite does. No CORS plugin is registered: a request with `Origin: https://evil.example` receives no `Access-Control-Allow-Origin` header (test).
- Caching: files under `/assets/` (content-hashed) get `Cache-Control: public, max-age=31536000, immutable`; `index.html` and other root files get `Cache-Control: no-cache` with an ETag. Dotfiles are denied, directory listings are off, and `/assets/..%2f..%2fpackage.json` returns 404 (path traversal test).
- SPA fallback: a GET or HEAD request outside `/api/`, `/healthz` and `/readyz`, whose path has no file extension and whose `Accept` includes `text/html`, receives `index.html` with 200. Every other unmatched request, including unknown `/api/*` paths, a missing `/assets/x.js` and any non-GET method, receives the standard `404` error envelope `{ "error": { "code": "not_found", "message", "requestId" } }`, never HTML.
- `securityHeaders` gains `img-src 'self' https://avatars.githubusercontent.com` (GitHub avatars) and nothing else: no `unsafe-inline`, no `data:`, no `blob:`, no other origin. The header snapshot test is updated, and every response for `index.html` carries the CSP, `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`.
- A Vitest test runs Vite's JavaScript build API with the real `vite.config.ts` into a temporary directory and asserts on the output: `index.html` has no inline script content, no inline `<style>`, no `on*=` attribute; no emitted CSS contains `url(data:`; every `<script>` and `<link>` URL is same-origin and relative.
- Typography uses a system font stack only (no web-font host), so the CSP needs no `font-src` addition. The test above fails if built CSS contains an `@import` or `url(` pointing at another origin.
- Boot test (E04 style): the app starts on PGlite with a fixture `WEB_ROOT`, `GET /` returns the fixture index with the CSP header, and `GET /readyz` still answers JSON.

**E17-S04 — Typed API client on shared contracts** ⬜ Todo
Acceptance criteria:
- `src/shared/contract.ts` exports `defineRoute({ method, path, params?, query?, body?, responses })`, where each schema is a zod schema and `responses` maps status codes to schemas. Route descriptors for the web client live in `src/shared`, so `src/shared` imports neither `src/server` nor `src/web`, and the server registers its routes from the same descriptors as they are touched. The error envelope of E04 (`errorResponseSchema`) is the default non-2xx shape.
- `createApiClient({ fetch, csrf })` returns `call(route, input, { signal })`: path parameters are `encodeURIComponent`-encoded (test with `a/b?c#d`), `undefined` query values are omitted, bodies are JSON with `content-type: application/json`, `credentials: 'same-origin'`, and no `Authorization` header is ever set.
- Responses are parsed strictly: a 2xx body that fails the route schema throws `ContractError` carrying the route name and the zod issue paths only (never data); a non-2xx body is parsed with the envelope into `ApiError { status, code, requestId, retryAfterSeconds? }`; a non-JSON error body becomes `ApiError` with code `unexpected_response`; a fetch rejection becomes `NetworkError`; an aborted call rejects with the original `AbortError`.
- CSRF: for any method other than GET and HEAD the client sends the CSRF token from the session query (E10 defines header name and source). The token lives only in memory. A `403` with code `csrf_invalid` triggers exactly one session refresh and exactly one retry of that request; a second failure surfaces the `ApiError`.
- `401` raises `ApiError` code `unauthenticated` and calls the `onUnauthenticated` callback registered by the auth layer (E17-S08). `429` exposes `retryAfterSeconds`, parsed from `Retry-After` in both its integer-seconds and HTTP-date forms. Non-idempotent requests are never retried automatically.
- `@tanstack/react-query` 5 is added with a `QueryClient` factory: `retry` is false for `ApiError` with status below 500 and at most 2 for others, `staleTime` 30 s, `gcTime` 5 min, mutations never retry.
- No token storage: ESLint `no-restricted-globals` forbids `localStorage` and `sessionStorage` in `src/web/**` except in `src/web/theme/storage.ts` (E17-S05), which stores a theme name only.
- MSW tests cover every branch above: success, schema mismatch (message contains no payload text), 400 envelope, 401, 403 with one retry then failure, 429 in both `Retry-After` forms, network error, abort, hostile path parameters, and the absence of `Authorization` and manually set `Cookie` headers.

**E17-S05 — Design tokens and light/dark theme** ⬜ Todo
Acceptance criteria:
- Tailwind CSS 4 through `@tailwindcss/vite`. `src/web/styles/tokens.css` defines colour, spacing, radius and type tokens as CSS custom properties on `:root` and redefines the colour tokens under `:root[data-theme="dark"]`; Tailwind's `@theme` maps to the tokens. A test fails when a hex or `rgb()` colour literal appears in `src/web` outside `tokens.css`.
- Theme modes are `system` (default), `light` and `dark`. `system` follows `prefers-color-scheme` live through the `matchMedia` change event. `<meta name="color-scheme" content="light dark">` is present and the CSS `color-scheme` property follows the active theme so native controls and scrollbars match.
- The choice is persisted by `src/web/theme/storage.ts` (the only module allowed to touch Web Storage) under key `cla.theme` with value `system`, `light` or `dark`. Every access sits in try/catch: when storage throws or holds anything else, the mode is `system` and the UI works. The module never stores a token or any other key (test).
- No flash of the wrong theme and no inline script: `src/web/theme/theme-init.ts` is built as a second, non-hashed entry emitted as `theme-init.js` and loaded as a blocking `<script src>` in `index.html`; it sets `data-theme` before first paint. Being a normal source file, it is linted, type-covered and unit-tested.
- `src/web/theme/contrast.test.ts` computes WCAG 2.2 contrast ratios for the declared foreground/background token pairs in both themes and fails below 4.5:1 for text and 3:1 for UI boundaries and the focus ring.
- A base `:focus-visible` rule gives every interactive element a visible 2 px ring using the focus token; `@media (prefers-reduced-motion: reduce)` disables transitions and animations, and `forced-colors: active` keeps borders visible (a test parses the stylesheet for each rule).
- `ThemeProvider` and `useTheme()` expose `{ mode, resolved, setMode }`; `setMode` applies `data-theme` and persists immediately. The visible toggle control is built in E17-S09 on the primitives of E17-S06.
- Tests: `setMode` updates `data-theme` and storage, a system preference change updates `resolved` while in `system` mode, a throwing storage does not break rendering, and an invalid stored value falls back to `system`.

**E17-S06 — Accessible form primitives and test helpers** ⬜ Todo
The form-level primitives E18 composes, each with the accessible name, keyboard behaviour and focus handling built in, plus the shared test helpers. Overlay and data primitives are E17-S10, built after the safe text component E17-S11, and E09-S01 (the shared hostile-name corpus) must be merged first.
Acceptance criteria:
- `radix-ui` (the single package, MIT) is added; components import only from it. Primitives in this story: `Button`, `Field`, `TextInput`, `Textarea`, `Checkbox`, `RadioGroup`, `Select` (native `<select>` wrapper), `Tabs`, `Badge` and `StatusMessage`. Copy-in component generators are not used (`docs/decisions.md` Decisions).
- `Button` has `primary`, `secondary`, `danger` and `ghost` variants; `loading` sets `aria-busy`, ignores clicks and keeps focus; an icon-only button is a type error unless `aria-label` is given.
- `Field` wires label, description and error with `useId`: `htmlFor`, `aria-describedby`, `aria-invalid`, `aria-required`, and the error text in a `role="alert"` node. Required fields also show visible "(required)" text from the catalog. `TextInput`, `Textarea`, `Checkbox` and `RadioGroup` render inside it.
- `Badge` always carries a text label; colour is never the only signal. Status-to-variant mapping is a typed record, so an unmapped status fails `tsc`. `StatusMessage` is a `role="status"` polite live region that other primitives reuse to announce changes.
- Test helpers live in `src/web/test-support/`: `expectNoA11yViolations(container)` runs `axe-core` (MPL-2.0, AGPLv3-compatible, dev dependency with recorded justification; its `color-contrast` rule is off in jsdom because E17-S05 covers contrast), and `expectHostileNamesInert(render)` imports the shared `HOSTILE_NAMES` corpus of E09-S01 (this epic defines no corpus of its own) and asserts for each entry that no `script`, `img` or `a[href^="javascript:"]` element exists and that the text is present as text.
- Every primitive in this story has a user-event keyboard test (Tab order, Enter, Space, Escape, arrow keys for `RadioGroup` and `Tabs`), an axe test, and a hostile-name test where it displays user text. No primitive uses `dangerouslySetInnerHTML`.

**E17-S07 — Request states and error boundaries** ⬜ Todo
Acceptance criteria:
- `LoadingState` renders `role="status"` with visually hidden text from the catalog and shows its spinner only after 200 ms (fake-timer test: a response arriving at 100 ms never flashes a spinner). `EmptyState` takes a heading level, a title, a description and an optional primary action. `ErrorState` renders `role="alert"`.
- `errorMessage(error)` maps `ApiError.code` to the catalog entry `errors.<code>` and falls back to `errors.unknown`; server wording is never displayed. A test enumerates the error codes exported by `src/shared` (the `errorResponseSchema` family plus the codes E10 and E11 add, and the client-side `network`, `contract` and `unexpected_response`) and fails when one has no catalog entry.
- `ErrorState` text comes from `errorMessage(error)`, never from `error.message`. It shows the request id in `<code>` with a copy button when the error is an `ApiError`, and a "Try again" button calling the supplied `refetch`. A `ContractError` shows the generic contract message and no payload text.
- A `429` error disables "Try again" and shows a countdown from `retryAfterSeconds` (fake-timer test), enabling the button at zero.
- `QueryBoundary({ query, isEmpty, children })` maps a `UseQueryResult` to loading, error, empty or data. On a refetch failure with existing data, the data stays visible and an inline `ErrorState` banner is added; it never swaps the page for an error.
- A root React error boundary and a TanStack Router `errorComponent` render a fallback with a "Reload" button and the request id when available. They log `error.name` and the request id to `console.error` only, with no network reporting and no payload, message text or stack sent anywhere. The footer (E17-S09) is rendered outside both boundaries.
- Router `notFoundComponent` renders a 404 page with a link home. An `ApiError` with status 403 renders the forbidden state, not a blank page.
- Focus: when an error state replaces content it is announced through `role="alert"`; when data replaces a loading state focus is not moved.
- MSW tests cover each transition (loading to data, to empty, to error, retry to data, refetch failure with stale data) and run the axe check on each state.

**E17-S08 — Authentication state, router and login/logout** ⬜ Todo
Consumes the session, login and logout contracts of E10.
Acceptance criteria:
- `@tanstack/react-router` is added. The route tree is code-based in `src/web/router.tsx` (no codegen, no `routeTree.gen.ts`), with a typed router context `{ queryClient }`. Every route declares `staticData: { access: 'public' | 'authenticated' }`; the type augmentation makes the field required, and a test walks the route tree and fails on a route without it.
- `useSession()` queries E10's current-session endpoint through the typed client and returns either `{ authenticated: false }` or the user (`githubId` numeric, `login`, `avatarUrl`) plus the CSRF token, held in the Query cache only. `staleTime` is 60 s with refetch on window focus. `avatarUrl` is accepted by the schema only when its origin is `https://avatars.githubusercontent.com`; otherwise the avatar falls back to initials.
- An unauthenticated visitor of an `authenticated` route is sent by a full-page navigation (not client routing) to E10's login-start route with `return_to` set to the current relative path plus search. `buildReturnTo` rejects anything that does not start with a single `/`, starts with `//`, or contains `\` or a control character (table test with `//evil.example`, `/\evil`, `https://evil.example`, `javascript:alert(1)`, encoded variants). Login start performs no mutation.
- Logout is a button in the user menu issuing E10's logout `POST` through the client (CSRF applies). On success `queryClient.clear()` runs, so no tenant data of the previous session survives, and the app navigates to `/`. A second click while pending sends nothing; a failure shows an `ErrorState`.
- When any call returns `unauthenticated` (idle or absolute expiry, or sessions deleted after a `github_app_authorization` revoke), the session query is invalidated, the cache is cleared and a non-blocking banner "Your session ended" with a login link (return path preserved) replaces the blank page; the form state the user was editing stays on screen.
- After a full login and logout flow driven by MSW, `localStorage.length` and `sessionStorage.length` are 0 and `document.cookie` is empty (the session cookie is `HttpOnly`); no token or session id appears in the DOM, the URL or `console` output (spy test).
- The route factory has no default for `access`. Routes declared in this epic: `/` (`public`, landing page with "Log in with GitHub"), `/login/failed` (`public`) and the not-found route (`public`). E18 registers `/sign/$githubRepoId` as `public` (it renders its own login prompt) and its maintainer screens as `authenticated`; E19 registers `/setup` and `/setup/callback` as `public`.
- `/login/failed?reason=<code>` is the target of E10's failure redirect. A catalog test enumerates the reason codes `state_mismatch`, `access_denied`, `exchange_failed`, `github_unavailable`, `unsupported_account` and `bad_request` and fails when one has no message under `login.failed.<code>`; an unknown or missing `reason` shows the generic message, never the raw query value. The page offers "Try again" (a full-page navigation to E10's login start) and a link home, and the footer stays visible.

**E17-S09 — Application shell, navigation and AGPL source footer** ⬜ Todo
Acceptance criteria:
- `AppShell` renders landmarks `<header>`, `<nav aria-label>`, `<main id="main" tabIndex={-1}>` and `<footer>`, with a "Skip to content" link as the first focusable element. Below 768 px the navigation collapses into a disclosure button with `aria-expanded` and `aria-controls`; the active link has `aria-current="page"`. Routes can supply a `headerSlot` (E18 puts the tenant switcher there).
- On every route change the page `<h1>` (or `main` when absent) receives focus, `document.title` becomes `<page title> · CLA` from the catalog through `usePageTitle`, and a polite live region announces the new title (user-event tests).
- The user menu shows the avatar and `login` through `UserText` (never the numeric id), the `ThemeToggle` and "Log out"; an unauthenticated visitor sees "Log in with GitHub" instead. `ThemeToggle` is a `RadioGroup` (system, light, dark) with catalog labels, operable by arrow keys, backed by `useTheme()` from E17-S05.
- `GET /api/meta` is public (added to `PUBLIC_ROUTES`, E11-S01), needs no session and has a descriptor in `src/shared` with response `{ "sourceUrl": string (https URL), "commit": string | null, "installUrl": string (https URL) | null }`. `installUrl` is `https://github.com/apps/<slug>/installations/new`, built from the App slug that the E05 start-up self-check verified (zod: slug `^[a-z0-9-]+$`), and `null` before the App is configured; E18-S04 uses it for the "Install on another organisation" link. The server reads `SOURCE_URL` (default `https://github.com/Axiumine/cla-gate`, https only, validated at start-up) and `SOURCE_COMMIT` (40 hex characters; unset, empty or `unknown` yields `null`), which E19 passes as a build argument when the operator builds the image locally. The response carries `Cache-Control: public, max-age=300`.
- The footer on every page, including the landing page, error pages and the not-found page, shows "Source code" linking to `<sourceUrl>/tree/<commit>` when a commit is known and to `<sourceUrl>` otherwise, the first 7 characters of the commit in `<code>`, and the licence name `AGPL-3.0-only`. Links use `rel="noopener noreferrer"`. This is the AGPL section 13 offer of corresponding source for the exact running version.
- The link can never disappear: if `/api/meta` fails or is slow, the footer renders the compiled-in `DEFAULT_SOURCE_URL` (exported from `src/shared`); the client re-validates `sourceUrl` with zod (https scheme, no credentials) before using it as an `href`, so a `javascript:` value is rejected.
- Tests cover: commit known, commit null, meta failing with the fallback link, a hostile `sourceUrl`, focus and title on navigation, the collapsing navigation by keyboard, and axe on authenticated and unauthenticated shells. The server side has a route test and a config test for both variables.

**E17-S10 — Overlay and data primitives** ⬜ Todo
The dialogs and tables E18 builds its screens from. Built after E17-S11, because `DataTable` cells and dialog text render user-controlled strings through `UserText`.
Acceptance criteria:
- `Dialog` and `AlertDialog` import only from `radix-ui`. Focus is trapped, focus returns to the trigger on close, Escape closes a `Dialog` but not an `AlertDialog` (which needs an explicit choice and focuses its cancel button first).
- Opening any overlay adds no `<style>` element to the document (radix's scroll lock helper injects one, which `style-src 'self'` blocks; the primitive disables it and locks scrolling with a class defined in the stylesheet). The CSP is not relaxed; the e2e run of E18-S12 asserts zero `securitypolicyviolation` events.
- `DataTable` renders a semantic `<table>` with a caption (visually hidden allowed), `scope="col"` headers, optional sort buttons with `aria-sort`, and an `emptyState` slot. Cells that show user text use `UserText`; a typed column definition makes a plain string cell for a user-controlled field a type error.
- `CursorPager` has Previous and Next buttons driven by opaque server cursors and announces the page change through `StatusMessage` (`role="status"`, polite). Both buttons are disabled while a page loads, and a stale cursor error leaves the current page on screen.
- Every primitive has a user-event keyboard test (Tab, Enter, Space, Escape), an axe test, and a hostile-name test (`expectHostileNamesInert`, E17-S06) where it displays user text. No primitive uses `dangerouslySetInnerHTML`.

**E17-S11 — Safe user text component** ⬜ Todo
One component through which every user-controlled string reaches the screen. Built before E17-S10.
Acceptance criteria:
- `UserText` renders any user-controlled string (names, logins, repo names, rationales) as a React text node inside `<bdi>` with `overflow-wrap: anywhere`. It never uses `dangerouslySetInnerHTML` and never interprets markdown or HTML.
- Unicode control and bidi formatting characters (C0 and C1 controls except newline, U+200E, U+200F, U+202A to U+202E, U+2066 to U+2069, U+FEFF) are shown as visible `<U+XXXX>` placeholders; the stored value is untouched. A table test covers each range boundary, a lone surrogate and a 4-byte emoji, which stays intact.
- Optional `maxLength` truncates with an ellipsis and keeps the full text available to assistive technology (the full text sits in a visually hidden node). A 10,000-character string without spaces does not widen its container (layout assertion on the computed style).
- Every entry of the shared `HOSTILE_NAMES` corpus (E09-S01) renders as text through `expectHostileNamesInert` (E17-S06), with an axe test, and a gate rule forbids `dangerouslySetInnerHTML` anywhere in `src/web` (the Biome rule `security/noDangerouslySetInnerHtml`, or an ESLint `no-restricted-syntax` selector if the Biome rule name does not exist; a fixture file proves the rule fires).
