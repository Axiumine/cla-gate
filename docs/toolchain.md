# Toolchain: tools, hooks and CI

Which tools run, when they run and what CI enforces. The thresholds are in [`quality-gates.md`](quality-gates.md), the scripts in [`development.md`](development.md), and the traps of each tool in [`tooling-gotchas.md`](tooling-gotchas.md).

Everything is strict by default: 100% coverage, zero lint findings, 100% type coverage, no unused code and ratcheted structural caps; the mutation score has a floor (Stryker, `break` 90), and every `any`, `as` and coverage-ignore comment needs a written reason. Hooks give fast local feedback; **CI is authoritative** because hooks are bypassable.

## Hook pipeline

Order is cheap and deterministic first, expensive and flaky last, and each step only runs if the previous one passed.

| Stage | Scope | Target budget | Jobs, in order |
|---|---|---|---|
| `pre-commit` | staged files | 15 s | 1. `biome check --write --error-on-warnings` (restages fixes). Then in parallel: ESLint on staged files, `vitest related --run` (no coverage), `check-code-caps`, `trivy fs --scanners secret` |
| `commit-msg` | none | n/a | Not used |
| `pre-push` | whole repo | 3 min | 1. `biome ci --error-on-warnings` 2. `tsc -b` 3. in parallel: ESLint full, the escape-hatch gate (`yarn lint:hatches`), `type-coverage --strict --at-least 100`, Knip (both modes), FTA, `check-code-caps`, the runner guard (`yarn ci:runners`), `trivy fs` (HIGH/CRITICAL plus secret/misconfig), Semgrep (skipped if not installed) 4. `CI=1 vitest run --coverage` at 100% |
| `post-merge`, `post-checkout`, `post-rewrite` | lockfile change | 1 min | `yarn install --immutable` when `yarn.lock` or `.yarnrc.yml` changed |

Every hook job has a CI counterpart, and the `pre-push` hook calls the same `package.json` scripts as CI and `yarn gate` (`yarn lint:biome`, `yarn typecheck`, `yarn lint:eslint`, `yarn lint:hatches`, `yarn type-coverage`, `yarn knip`, `yarn fta`, `yarn caps`, `yarn semgrep`, `yarn trivy`, `yarn ci:runners`, `yarn coverage`). `pre-commit` runs staged-file variants of the binaries (`biome check --write`, `eslint`, `vitest related`) and shares `yarn caps` and `yarn trivy:secrets`. `skip: [merge, rebase]` is set on the slow `pre-commit` jobs only; on `pre-push` it would let `yarn gate` pass without running during a rebase. Budgets are targets, not measurements. `lefthook.yml` uses `piped: true` so a failed step stops the rest, with `group: parallel` for the independent static checks in step 3. Formatting runs before linting so lint sees the final text; types run before tests; coverage is last in the hook because it is the most expensive and meaningless if static gates fail. `CI=1` makes Vitest refuse to write new snapshots, so a push cannot go green with uncommitted snapshot files. Mutation, e2e, leak and Qodana runs are nondeterministic or slow and stay in CI.

Network-bound jobs (Trivy vulnerability DB, Semgrep registry rules) can be skipped offline with `LEFTHOOK_EXCLUDE=trivy,semgrep`, which excludes both `trivy` jobs (pre-commit and pre-push) and the `semgrep` job; that is the only sanctioned hook exclusion, and CI still enforces them. Downloading Semgrep rules into a git-ignored `rules/` cache removes the registry dependency; do not commit them (see [`docs/tooling-gotchas.md`](tooling-gotchas.md), Semgrep).

## CI (authoritative)

`.github/workflows/ci.yml`, every third-party Action pinned to a full commit SHA. Every job below exists. All but `qodana` (the one job that holds a secret) run on the maintainer's shared, persistent, self-hosted runners (`runs-on: [self-hosted, Linux, X64]`), protected only by the fork-PR approval gate; `qodana` runs on GitHub-hosted `ubuntu-24.04`. On the nightly schedule every job runs (the `trivy` job also scans dev dependencies, `mutation` adds `--force` and skips a shard that already passed on the same commit), and the concurrency group includes the event name so a queued nightly run is never replaced by a push; the policy, the risks, the job rules and the port rules are in [`docs/ci-runners.md`](ci-runners.md). Every job starts with a fail-fast preflight (git, curl, tar, free disk space, and Docker for `postgres`) and keeps Corepack (installed into a per-job prefix, not the shared tool cache), Yarn, npm, the XDG directories and `TMPDIR` under the runner's temp directory. CI installs no git hooks: on a persistent workspace one would fail the next run's checkout. `release.yml` and `scorecard.yml`, if they are ever added, must use GitHub-hosted `ubuntu-24.04`. Job graph:

| Job | Needs | Runs |
|---|---|---|
| `static` | none | Explicit named steps running the same scripts as the `pre-push` hook minus the coverage step: Biome, `tsc -b`, ESLint, the escape-hatch gate (step `Escape hatches (justification gate)`), type-coverage per project, Knip (both modes), FTA, caps, and the runner guard `yarn ci:runners` (every job must name an allowed runner, have a timeout of at most 60 minutes, least-privilege permissions and no `container:` or `services:`; see `docs/ci-runners.md`) |
| `coverage` | none | `CI=1 vitest run --coverage` at 100%. Runs in parallel with `static` (both are required checks, so a skipped dependent job could not mask a failure). Uploads `coverage/lcov.info` as the artifact `coverage-lcov` (1 day) for Qodana |
| `postgres` | none | `yarn ci:postgres start` runs a PostgreSQL 18 container (image pinned by tag and digest, no `services:` block) on a random free loopback port with a unique per-run name and password, and exports `DATABASE_URL`; then `yarn test`; an `if: always()` step runs `yarn ci:postgres stop`. The Vitest globalSetup creates a throw-away `cla_test_<hex>` database, the whole suite runs in it, and it is dropped afterwards. Runs with `REQUIRE_REAL_POSTGRES=1` and `CLA_ROLE_TESTS=1` and writes `select version()` to the job summary. Its `timeout-minutes` is 45, not 20: the suite grows with every epic and the shared runners cancelled the job twice at 20 minutes while the tests still passed. Informative until E20-S12 promotes it; it exists to catch a difference between PGlite and a real server (the real-Postgres-only concurrency tests only run here) | It also runs the real-Postgres-only test of the test-database guard (a sentinel database that holds `schema_migrations` must come out of a run untouched).
| `mutation` | `static` | A matrix of seventeen shards (`scripts/mutation-gate/shards.ts`: sixteen for the server and shared code, one for the caps tool), `fail-fast: false`, `max-parallel: 1` (2 until 2026-11-03), 180 minutes each (the one job the guard lets run longer than the 60-minute policy cap, R4: the initial test run of the whole server suite is repeated by every shard and is given up to 120 minutes; Stryker is stopped after 170 so that the save and upload steps run). Only on the nightly schedule, a manual run and a `v*` tag push: not on pull requests, not on a push to `main`. Skip when nothing changed (E20-S04): on the schedule only, the first step after Node (`decide`, `scripts/mutation-gate/decide-skip.ts`, GET only, `permissions: actions: read, contents: read`) skips the whole leg when the newest earlier nightly run of the same commit that has the job `mutation (<shard>)` concluded it `success`, and fails open (any error means the shard runs). Per shard, `yarn mutate:shard` with its incremental file restored from a cache keyed by the shard, the lockfile, Node, the Stryker and Vitest configs and the tsconfig files, and saved again by `actions/cache/save` even when the run failed or timed out; `yarn mutate:check-incremental` runs after the restore and before the save and deletes a file Stryker cannot read, so that a broken file is never cached. A manual run with `force`, and the nightly run, add `--force`; a manual run can pick one `shard`. Uploads `reports/mutation/<shard>/` as `mutation-report-<shard>` (7 days) |
| `e2e` | `static` | Playwright in the pinned container (tag and digest) against the built server on a migrated PostgreSQL 18, then two baseline updates that must agree with each other and leave `git status` of `e2e/__screenshots__` clean. Uploads the report and traces on failure (7 days) |
| `caddy` | none | Informative. `yarn ci:caddy validate` runs `caddy validate` on `docker/Caddyfile` in a throw-away container of the pinned image (`--network none`, no published port) for `https://localhost` and `https://cla.example.com`; `yarn ci:caddy stop` in an `if: always()` step removes it. 10 minutes |
| `container` | none | Informative, 15 minutes. Validates the compose file in both profiles, then `yarn smoke` builds the image from the checkout and runs the operator stack in labelled containers (boot and setup mode, the compose files, hardening, the database roles, configured mode, failure injection, backup and restore, TLS); `yarn ci:smoke stop` sweeps what the run left; the compose logs of a failure are the artifact `smoke-compose-logs`. Becomes required once stable |
| `semgrep` | none | Full scan (`yarn semgrep`), installed with pipx at the exact version also pinned in `mise.toml` (currently 1.183.0; a test keeps the two equal, so bump both together); informative until E20-S10; no SARIF upload, no cache of the rules |
| `trivy` | none | `yarn trivy`, plus `yarn trivy:dev` on the nightly schedule; informative until E20-S11 |
| `leaks` | `coverage` | memlab (`yarn leaks:control`, then `yarn leaks`); nightly, manual run and `v*` tags only. Never required |
| `qodana` | `coverage` | Maintainer-side; GitHub-hosted; skipped for fork PRs and when `QODANA_TOKEN` is absent; never required |

Branch protection on `main` requires `static` and `coverage` today; `semgrep`, `trivy`, `postgres`, `mutation`, `e2e` and `container` become required one at a time once they are stable in CI (see [`CONTRIBUTING.md`](../CONTRIBUTING.md), Repository protection, for the definition of stable and the promotion template); `leaks` and `qodana` never do. `scripts/ci-contract.test.ts` keeps `ci.yml` honest (pinned actions, no `pull_request_target`, the required jobs exist under their exact names). `yarn gate` is the local equivalent of `static` plus `coverage`. Dependabot (`.github/dependabot.yml`) keeps the SHA-pinned Actions and the npm dependencies current, with a one-week cooldown, grouped; TypeScript stays on 6.0.x. The groups `playwright` (`@playwright/test`), `stryker` (`@stryker-mutator/*`) and `memlab` (`memlab`, `@memlab/api`) sit above the catch-all and set no `update-types`, because a dependency joins the first matching group and these move in lockstep (a `@playwright/test` bump must also bump the `e2e:update` image and the `E2E_IMAGE` tag and digest, which `scripts/e2e-pin.test.ts` enforces).
