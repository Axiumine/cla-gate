# Quality gates

The thresholds every change must meet, the TypeScript setup behind them and the testing conventions. The scripts that run the gates are in [`development.md`](development.md); the hard rules that forbid bypassing them are in [`CLAUDE.md`](../CLAUDE.md).

## Thresholds

| Gate | Threshold |
|---|---|
| Vitest coverage (v8) | `thresholds: { 100: true }` (lines, branches, functions, statements); `coverage.include: ['src/**/*.{ts,tsx}', 'scripts/**/*.ts']` so unloaded files count. **Fixed exclusion list (the only one):** `**/*.test.{ts,tsx}`, `**/*.d.ts`, test setup files, MSW handlers, `e2e/`, `tests/leaks/`, root tooling config files. Application entrypoints stay in scope: keep them logic-free and cover them with a boot test (start the app on PGlite, hit a health route; `main.ts` and `migrate.ts` have one). `vitest.config.ts` has two projects, `scripts` and `server` (the `web` project joins with `src/web`). The one test setup file on the exclusion list today is `src/server/adapters/db/global-setup.ts` (`**/global-setup.ts`): Vitest runs it once in the main process, outside the coverage-instrumented workers, so it can never be covered; it only creates and drops the throw-away database. Entries for MSW handlers join the list when those files do |
| type-coverage | `--strict --at-least 100`, per tsconfig project |
| ESLint | `--max-warnings 0`; `complexity: ['error', 10]`; `max-lines` 500, `max-lines-per-function` 50, `max-params` 4, `max-depth` 4 as **errors**, with counting options (`skipBlankLines`, `skipComments`) set to match the caps script so both agree. One known difference: `max-params` also counts a typed `this` parameter, which the caps tool treats as free (ESLint is the stricter side; `@typescript-eslint/max-params` only skips `this: void`, so it would not align them). The rules apply to every extension the caps tool measures (`.ts .tsx .mts .cts .js .jsx .mjs .cjs`); a file outside every tsconfig project fails with a project-service parse error. There is no ESLint class-size rule and no ratchet: the script stays the gate |
| Biome | `complexity/noExcessiveCognitiveComplexity` level `error`, `maxAllowedComplexity: 10` (it is cognitive, not cyclomatic, and `info` by default); `--error-on-warnings` everywhere; disable sonarjs's duplicate `cognitive-complexity` |
| check-code-caps | file 500, function 50, class 300, params 4, nesting 4; ratchet vs `.code-caps-baseline.json`; fails on any new or **grown** violation. Greenfield baseline is empty. **Tests obey the same caps** (the maintainer's convention): write flat `test()` / `test.each()` tables, no `describe` wrapper around a whole file, at most 4 parameters or fixtures per test, split files by topic. Details in [`scripts/code-caps/README.md`](../scripts/code-caps/README.md) |
| FTA | `score_cap: 50`; the run fails when score is above 50 (per source code; the docs say below 50 is OK, so exactly 50 is ambiguous), which rules out the "could be better" band too. Exclude tests via `exclude_filenames` (`*.test.ts`, `*.test.tsx`, `test-support.ts`, `*.d.ts`); `fta-cli` pinned exactly |
| Stryker | `thresholds.break: 90` initially, raise as the score allows, never lower. `--incremental`. Packages: `@stryker-mutator/core`, `vitest-runner`, `typescript-checker` (all 10.1+), `checkers: ['typescript']` with `tsconfigFile` pointing at the server project. Scope: server and domain code (`src/server/domain/evaluation/` first: every rule has a row that fails when its condition is flipped; the lower-casing of `finding.sha` in `unlinked.ts` is an equivalent mutant, because extraction already lower-cases it); the web project is outside the floor until a plan exists |
| Knip | zero issues in both modes |
| Trivy | HIGH and CRITICAL vulnerabilities fail; any secret or misconfiguration fails; `--exit-code 1` must be explicit (default is 0) |
| Semgrep | any finding fails (`--error`) |

## TypeScript

- Single compiler: `typescript` pinned to `~6.0.x`. **Do not upgrade to 7.x.** TS 7 ships no compiler API (7.1 adds a different one) and typescript-eslint 8.72 peers `typescript <6.1`. Stryker's typescript-checker, `type-coverage --strict` and `scripts/check-code-caps.ts` need the classic API. Revisit when typescript-eslint supports TS 7.1.
- Required compiler options: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `verbatimModuleSyntax`, `erasableSyntaxOnly`. Library code uses `allowImportingTsExtensions` or `rewriteRelativeImportExtensions` as appropriate.
- Project layout: solution-style root `tsconfig.json` (`files: []`) referencing app (bundler resolution, DOM, `noEmit`), server (`nodenext`, `composite`, explicit `rootDir` and `outDir`, emit excludes `**/*.test.ts`), scripts (`nodenext`, `noEmit`), e2e (Playwright specs and `tests/leaks`, `noEmit`), and node-config (`vite.config.ts`, `playwright.config.ts`, Stryker/ESLint config, `noEmit`). Unit tests are co-located and typechecked in their owning project. Every project gets the strict flags, type-coverage and ESLint `projectService` coverage. `package.json` has `"type": "module"`. **Today** the root `tsconfig.json` references `tsconfig.server.json` (`src/server` and `src/shared`: `nodenext`, `composite`, `rootDir: src`, `outDir: dist`, `rewriteRelativeImportExtensions` so `.ts` specifiers become `.js`; excludes `*.test.ts`, `test-support.ts`, `global-setup.ts` and the PGlite adapter, which are test-only), `tsconfig.server.test.json` (`noEmit`, `allowImportingTsExtensions`, the same sources plus every test and helper: this is the project ESLint and type-coverage see for them), `tsconfig.scripts.json` (`scripts/**/*.ts`, `allowImportingTsExtensions`) and `tsconfig.node.json` (`*.config.ts`, `*.config.mjs`, `types/**/*.d.ts`, `allowJs` and `checkJs` so `eslint.config.mjs` is typed and linted); both extend `tsconfig.base.json`, which holds the strict flags plus `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns` and `noFallthroughCasesInSwitch`, and keep their `tsBuildInfoFile` under `node_modules/.tmp`. Referenced `noEmit` projects work with `tsc -b` without `composite`. TS 6 defaults: `strict: true`, `types: []` (list `node` and `vite/client` explicitly), default `rootDir` is the tsconfig dir (set it).
- `tsc -b` is whole-project; gitignore `*.tsbuildinfo` (they live under `node_modules/.tmp`). Caching them in CI is deferred: `ci.yml` caches only the Yarn cache.
- Scripts run natively: `node scripts/foo.ts`. Native type stripping is stable in Node 26 but accepts **erasable syntax only**: no `enum`, no runtime `namespace`, no constructor parameter properties, `import type` for types, explicit `.ts` extensions, and Node ignores `tsconfig.json` (use `#subpath` imports, not `paths`). `typescript` is loaded from `node_modules` as plain JS, which is fine; it must be the 6.x package, and only the default import (`import ts from 'typescript'`) is verified, so do not use named imports until tested.

## Testing

- Vitest `projects`: `scripts` and `server` (node environment) today; `web` (jsdom + Testing Library + user-event + jest-dom + MSW 3) joins with `src/web`. Coverage is process-wide, run once with `yarn coverage`. The 100% gate runs in jsdom, not Vitest Browser Mode (v8 coverage is Chromium-only there).
- Database tests use PGlite (single connection, in-memory, Postgres 18) by default. CI also runs the suite against a real Postgres 18 container via `DATABASE_URL` (the informative `postgres` job). `PGlite` is pinned exactly (`0.5.14` is PostgreSQL 18.6); minor upgrades may change on-disk format.
- **How a test gets a database:** import from `src/server/adapters/db/test-support.ts` and nothing else. `migratedTestDatabase()` (all migrations applied) or `emptyTestDatabase()` return `{ kind, db }` on one shared connection per test file and reset the `public` schema (`drop schema public cascade`) before each call, so tests never see each other's rows. `migratedRuntimeDatabase()` is the same with `cla_app` created first, so its grants exist, and `containing(text)` is a typed `expect.stringContaining` for error-message matchers (assert the message, not only the SQLSTATE, so a dropped trigger cannot hide behind another one that raises the same code). `seedTenant(db, n)` inserts an installation, repository, document and published version 1.0 with ids derived from `n` (two tenants: `n = 1, 2`), `seedSignature(db, tenant, githubUserId)` adds a user, signature and `signer_pii`, `publishVersion` adds a version, `ensureRuntimeRole(db)` creates `cla_app` (a cluster-wide object) and `asRuntimeRole(db, work)` runs `work` in a transaction under `set local role cla_app`, which is how tests prove what the unprivileged role can and cannot do. `realPostgres` is true when the run uses a server; use `test.skipIf(!realPostgres)` only for what PGlite cannot do (today only the advisory-lock contention test). Files run one at a time on a real server (`fileParallelism: !realPostgres`), in parallel on PGlite. Tests that need a migrations folder use `writeMigrationDirectory({ name: sql })`.
- **Domain tests:** the tests next to `src/server/domain` build their facts with `src/server/domain/evaluation/test-support.ts` (a relative import; the `src/shared` one is `src/shared/test-support.ts`). Both are negated from the Knip production project like the adapters' one. Rules that are about cost are tested by counting reads or lookups (a Proxy over the input, a spy on `Map.prototype.get`), never by a clock, because the domain code and its tests may not use `performance` or `Date`.
- **Real-server runs:** with `DATABASE_URL` set, `src/server/adapters/db/global-setup.ts` creates `cla_test_<hex>` (the user needs CREATEDB), hands the URL to the workers through Vitest's `provide`/`inject`, and drops the database afterwards. It never touches the database the URL names.
- Snapshots: `toMatchInlineSnapshot` for small values; `toMatchSnapshot` only for small structural output where an inline literal would be noise; `toMatchFileSnapshot` for API JSON and CSV export, into a dedicated directory, never `__snapshots__/*.snap`. With `CI` set Vitest writes no snapshots and fails on missing ones; outside CI it writes them and passes, so the gate always runs with `CI=1` and new snapshot files must be committed.
- Vitest 5 defaults: `clearMocks: true`, fails on unawaited `expect().resolves/rejects`, no config search in parent dirs, reports under `.vitest/`. `vite` is now an explicit peer: add it as a devDependency. `@vitest/coverage-v8` must match the exact Vitest version.
- Vitest `related` needs `--run` and `--passWithNoTests`; never add `--coverage` to it (100% thresholds fail on partial runs).
- Stryker: use `@stryker-mutator/*` 10.1+ (Vitest 5 support landed in 10.1.0). It forces coverage off and one worker, so mutate only the node/unit project. Open bugs: `--logLevel debug` crashes on Vitest 5 (#6272), nondeterministic perTest verdicts (#6073); Browser Mode unsupported. Gitignore `.stryker-tmp`; cache `reports/stryker-incremental.json` in CI. Incremental misses dependency, env and snapshot changes: use `--force` after those.
- Playwright: visual baselines come from one environment. Image tag must equal the package version exactly (`mcr.microsoft.com/playwright:v<version>-noble`), run with `--init --ipc=host`. Never regenerate baselines on the host. Omit `{platform}` from `snapshotPathTemplate`. `animations: 'disabled'` is default; set `maxDiffPixels` explicitly. Bump image and package together.
- memlab 2.x drives Chromium through Puppeteer (separate browser download; `--chromium-binary` can reuse one). No leak-based exit code was found (unverified). Wrap it with `@memlab/api` `run()` and fail on `leaks.length`; the wrapper lives in `tests/leaks/`. Node 26 compatibility is unverified: smoke-test first. Use `vitest --logHeapUsage` and `node --heap-prof` / `--cpu-prof` for diagnosis.

## Escape hatches (hard rule 3)

Hard rule 3 of [`CLAUDE.md`](../CLAUDE.md) in full:

- **No escape hatches without a reason.** `any`, `as` assertions (`type-coverage --strict` penalises them), `@ts-expect-error`, `eslint-disable`, `biome-ignore`, `v8 ignore` are last resorts, each with a written justification on the same line. `reportUnusedDisableDirectives` stays on. Prefer zod parsing and type guards over assertions. The one `as` in the code base (`toExecResult` in `src/server/adapters/db/pglite/results.ts`, PGlite's untyped `exec()` rows) carries `// type-coverage:ignore-next-line -- reason`, which type-coverage honours without a flag. Any `v8 ignore` needs `-- @preserve` or the bundler strips it.
